Ambiguous upstream mutations still need manual reconciliation, but that requirement is identical under dedicated and shared placement and is not a placement blocker. None is asserted certified or production-shared. The source tree identities include integration-only SDK requirement corrections: the four Runner candidates from `8bb55ec` now require `langbot-plugin>=0.7.4,<0.8`, and LangRAG now requires the same instead of `==0.6.1`; their source trees therefore intentionally differ from the lane tips. The KE `shared_subprocess_probe.py` and checked-in JSON evidence use a real SDK child and local Host vector/storage/embedding fixtures; the probe now takes a connector directory too, so all five KnowledgeEngine candidates have real-child two-binding evidence, and `verify_candidates.py` builds and exercises all five archives, LongTermMemory included. LongTermMemory's former in-probe manifest override is no longer the placement difference. These demonstrate only the operations actually invoked, not real vendor/provider execution. RunnerDemo's two-binding proof is in-tree and reproducible now (`RunnerDemo/tests/test_shared_runtime.py`: one real SDK worker, two `InstallationBinding`s, both resolving to the same `PluginContainer`, including through the handler's own slot registry; its identity assertions were shown to fail against a per-binding container mutation using a throwaway harness that is not committed). The earlier-lane archive `f790d29d…` is not in this tree and nothing here is the archive of this integrated PR head. The four-Runner lane does not provide real provider acceptance. Real provider-account invocation, signed/downloaded ZIP identity, independent review, production sandbox/network policy, and two real Cloud Workspace installations sharing the same certified digest remain unproven. External KE connector cancellation races and LongTermMemory's Tool/Command/EventListener write paths are still release gates; do not interpret a successful local fixture or a marketplace badge as production proof.
