# 单次上下文组装的计数去重基准

关联 [LangBot #2716](https://github.com/langbot-app/LangBot/issues/2716)。本基准比较固定 Git 基线与当前源码，定位重复计数 RPC 的局部成本。

## 行为边界

- 每次 `ContextCompactor.compact_async()` 创建独立计数作用域，后续轮次和并发组装不共享结果。
- 键使用 SDK 计数 API 同样的完整 `message.model_dump()` 值，递归冻结为带类型的不可变元组，保留消息顺序、角色、工具参数、多模态和 provider 字段。布尔值/整数、正负零、嵌套模型中的空值分别保留；字典顺序不同只会保守地少命中。消息每次重新取快照，原地修改后重新计数。
- 仅保存成功的真实计数；空列表仍调用 Host，零值和非零值均原样保留。usage anchor 的合成值不写入完整上下文计数缓存。
- 最多保留 128 项完整值快照和整数，新的输入超过容量后继续直接计数。快照仅引用不可变的原始标量，不保存可变 Message/字典/列表；大型字符串不复制或重新 JSON 编码。作用域内可能延长被截断字符串的生命周期，组装结束即释放。未知值或无法冻结的输入直接交给原计数器。
- 错误和取消正常传播；不修改 Host 授权、取消轮询、上下文压缩策略或模型计数协议。
- 没有新增依赖、环境变量、配置项、API 或数据库迁移。

## 复现

从仓库根目录执行：

```bash
cd Runner/LocalAgent
uv sync --locked --extra dev --python 3.11
uv run --no-sync pytest tests/test_context_token_counts.py -q
uv run --no-sync python benchmarks/context_token_counts.py \
  --baseline-ref 7b532cfd6222aa79f05f113b4db6c876d4782434 \
  --samples 20 --warmup 2 --delays-ms 0 2 10 --concurrency 1 8 \
  > /tmp/localagent-context-token-counts.json
```

基线提交必须存在于本地 Git 对象库。浅克隆缺少该对象时，先在仓库根目录执行：

```bash
git fetch origin 7b532cfd6222aa79f05f113b4db6c876d4782434
```

脚本通过 `git show` 加载基线的真实 `context_pipeline.py`，不复制旧算法。基线和当前实现共用确定性的 Host 替身：每次返回 `7 + 消息 JSON 字符数`，并用 `asyncio.sleep` 模拟指定的 RPC 延迟。空消息仍计为 7。该替身用于比较控制流和调用次数，不代表任何真实模型的 tokenizer。

每组先预热 2 个批次，再计时 20 个批次；并发 1/8 分别得到 20/160 次组装样本。基线与当前交替执行，每批在同一 compactor 上并发组装；完整输出比较在计时批次结束后进行，避免比较工作干扰同批任务的耗时。每个输出的消息、frame、压缩结果和 diagnostics 必须与基线完全一致，否则脚本报错。P95 使用 nearest-rank。

JSON 输出包含 Python、SDK、Pydantic 和系统版本、固定基线 commit、当前 HEAD、源码是否修改、源码 SHA-256、样本数、耗时中位数/P95及 Host 调用次数，不包含消息内容。

## 结果适用范围

结果衡量本地上下文组装和确定性 Host 替身调用。计时包含消息复制、值快照、计数替身的 JSON 编码和模拟等待；零延迟结果用于观察新增本地开销。模拟的 2/10 ms 不是实测生产 RPC 延迟。

本基准不包含真实 Core / Runtime RPC、模型服务、数据库、Docker Box 或 IM 投递，不证明多群吞吐、线上 P95 或 #2716 全部超时问题已经解决。生产收益仍需在相同负载、版本和部署条件下复测。
